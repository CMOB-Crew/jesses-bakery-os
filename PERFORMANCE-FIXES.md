### 1. Check the login once per page, not twice

<!-- card:auth-once -->
- [ ] Done
- Size: Medium change. Gains: makes it faster, costs less to run.

**Problem.** Every page asks the login server "is this person signed in?" twice. Once in the request gate, once again inside the page. Each ask is a network trip and takes about half a second.

**Fix.** Use the built-in `getClaims()` check in all three places (the request gate, the page-side session read and the token verifier). Separately, a PERSON switches the Supabase project to asymmetric JWT signing keys (dashboard: Settings → JWT Keys). The code change is safe in either order: with the old shared secret `getClaims()` still asks the server, so the speed gain only arrives after the dashboard step. The agent cannot do the dashboard step; make the code change, then tell the project owner the dashboard step is waiting.

**Where.**
- `apps/web/lib/supabase/proxy.ts:61`
- `apps/web/lib/supabase/server.ts:110`
- `apps/web/lib/auth.ts:41`

**Check.** Locally: `npx tsx scripts/proxy-matcher-check.ts` passes and `npm run build` passes (auth is off locally, so that is all a machine can check). On the preview site, signed in: pages load and the sidebar shows your name; signed out: protected pages redirect to login. After the dashboard step, the `[auth-verify]` line in the Netlify function log (turn on `SLOW_QUERY_MS`) drops from about 500 ms to a few ms.

**Example** (shape only, not real code):

Before:
```
const { data } = await supabase.auth.getUser();
// network call, ~500 ms
```
After:
```
const { data } = await supabase.auth.getClaims();
// checked locally, ~0 ms
```

### 4. Keep packing and driver ticks when the Wi-Fi drops

<!-- card:floor-outbox -->
- [ ] Done
- Size: Big change. Gains: stops lost work.

**Problem.** On the packing, driver, production and deliveries screens, a tick is sent to the server straight away. If that request fails, the tick still looks saved on screen. It disappears on the next reload. A driver in a dock with no signal loses the delivery.

**Fix.** Save each change on the device first (a small `localStorage` outbox, one queue per screen and day, keeping only the latest change per store), then send it. When the page opens or the browser fires `online`, resend anything that did not get through. Always check the reply and show "not saved yet" while anything is waiting. One shared hook in `lib/` used by all four screens; do not write four copies.

**Where.**
- `apps/web/components/PackingApp.tsx:142`
- `apps/web/components/PackingApp.tsx:170`
- `apps/web/components/DriverApp.tsx:107`
- `apps/web/components/ProductionBoard.tsx:217`
- `apps/web/components/DeliveriesBoard.tsx:89`

**Check.** With the page open in a browser, stop the local server, tick three lines: the "not saved yet" bar appears and the queue has entries. Start the server again and fire `window.dispatchEvent(new Event('online'))` in the console (or wait for the next tap): the bar goes and the queue empties. Reload: the three ticks are there. (A page cannot be reloaded while the server is off, so do not test it that way.)

**Example** (shape only, not real code):

Before:
```
await saveTick(change);
// if this fails, the change is gone
```
After:
```
await outbox.add(change);   // on the device
const res = await saveTick(change);
if (res.ok) await outbox.remove(change);
// on load + when back online: resend outbox
```

### 6. Reuse the big store table instead of rebuilding it on every page

<!-- card:store-week-cache -->
- [ ] Done
- Size: Medium change. Gains: makes it faster, costs less to run.

**Problem.** The main store table takes about a second for the database to compute. It only changes when a sales file loads overnight. Ten different pages ask for it fresh on every visit.

**Fix.** Wrap the read in `unstable_cache` so it is computed once and reused for an hour. The cached function cannot read cookies, and row-level security needs the signed-in user, so pass the session claims in as an argument and run the query with `runAsUser` inside. Callers get the claims from the already-cached `getSessionClaims()`. Mark it stale at the end of a feed load with `revalidateTag("store-week", "max")` from the ingest route. This is an app-side cache and does not change the database.

**Where.**
- `apps/web/lib/queries.ts:75`
- `apps/web/lib/db.ts:58`
- `apps/web/lib/feeds/ingest.ts:158`

**Check.** Locally (auth is off): build, start the production server, load the Overview twice; the second load is faster and shows the same numbers, and an entry appears in `.next/cache/fetch-cache/`. The signed-in and signed-out parts can only be checked on the preview site with `AUTH_ENFORCED=1`: the same numbers while signed in, nothing while signed out. A feed upload makes the next load show the new numbers.

**Example** (shape only, not real code):

Before:
```
export async function getStoreWeek() {
  return sql`select * from v_store_week`;
}
// page: getStoreWeek()
```
After:
```
export const getStoreWeek = unstable_cache(
  (claims) => runAsUser(claims, tx => tx`select * from v_store_week`),
  ["store-week"],
  { revalidate: 3600, tags: ["store-week"] });
// page: getStoreWeek(await getSessionClaims())
// ingest route, after a load: revalidateTag("store-week", "max")
```

## Words used here

- **Trip to the database.** One request from the app server to the database and back. The two live in different places, so each trip is about 0.13 seconds. Fewer trips is the biggest speed lever in this app.
- **Bundle (transaction).** A group of database statements sent together that either all succeed or all fail. `withUser()` in `lib/db.ts` opens one bundle per page request.
- **Cache.** Keep a result and reuse it instead of working it out again. React `cache()` reuses within one page load. `unstable_cache` reuses across visits for a set time. Both live in the app, not the database.
- **Claims-as-argument recipe.** How every `unstable_cache` in this app must be written. The cached function cannot read cookies, and the database only returns rows for a signed-in user, so the page passes the session claims in as an argument and the cached function runs its query with `runAsUser(claims, …)`. The cache is then per person, which is fine for about 40 users.
- **useMemo.** A React hook that remembers a calculation until its inputs change, so it is not redone on every click.
- **memo().** Wraps a small component so it only redraws when its own inputs change, not every time its parent redraws.
- **useDeferredValue.** Lets the search box update instantly while the filtered list catches up a moment later, so typing never stutters.
- **React Compiler.** A build step that adds `useMemo` and `memo` for you. Turned on with two lines in `next.config.ts`.
- **Wait, then save once.** Also called debouncing. Instead of saving on every tap, wait until the taps stop for a moment and save the final result once.
- **Outbox.** A list of changes saved on the device that still need to reach the server. Resent when the connection is back.
- **content-visibility.** A CSS rule that tells the browser to skip drawing rows that are off screen.
- **Packing and driver screens.** The tablet and phone screens used in the bakery and on the road: Packing, Driver, Production, Deliveries.
